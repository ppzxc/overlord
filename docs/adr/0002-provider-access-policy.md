# 예약처 접근 원칙: 방문자 브라우저의 조회 흐름까지 따라가고, 봇 탐지와 robots 금지는 넘지 않는다

전국 지자체·공공기관 캠핑장 예약처를 조사해 보니 공개 GET만으로 잔여가 나오는 곳이 없었다([#52](https://github.com/ppzxc/overlord/issues/52)). 잔여는 대기열 뒤에 있거나(숲나들e, 국립공원, 미리해), POST로 오거나(국립공원, xticket, 서울시, 땡큐캠핑), 봇 탐지 장치나 robots 금지 뒤에 있다. 그래서 [ADR 0001](0001-donghae-netfunnel-participation.md)이 동해시에만 허용한 방식을 모든 예약처의 원칙으로 넓힌다([#55](https://github.com/ppzxc/overlord/issues/55)).

"읽기 전용"은 HTTP 메서드가 아니라 **예약 상태를 바꾸지 않는 것**을 뜻한다. 로그아웃한 방문자의 브라우저가 조회 흐름에서 페이지 JS대로 보내는 요청이라면 보낸다. 대기열 참여(NetFunnel이든 미리해의 자체 게이트든)와 조회용 POST도 여기에 든다. 대기열 키 다루기와 차단 응답 처리는 ADR 0001의 규칙을 그대로 따른다. 예약, 결제, 취소, 회원정보 경로는 예약처마다 접근 금지 목록에 넣는다. 예약 단계에만 있는 로그인이나 캡차는 대상에서 빼는 이유가 되지 않는다.

넘지 않는 선은 세 가지다.

- **조회에 로그인이나 캡차가 필요한 곳**은 대상이 아니다.
- **잔여 경로가 봇 탐지 장치 뒤에 있는 곳**(서울시 dynapath, 땡큐캠핑 STCLab botmanager)은 평범한 요청이 통과하더라도 대상이 아니다. 대기열은 순서를 정하는 장치라 참여해도 운영자 의도에 맞는다. 봇 탐지는 우리 같은 클라이언트를 막으려는 장치라서, 그것을 두었다는 것 자체를 거절로 본다.
- **robots.txt가 감시 경로를 금지하는 곳**(인터파크, `gwgs.pubcamping.kr`)은 대상이 아니다. 파일이 없거나 열 수 없으면 금지가 없다고 본다.

## 고려한 대안

- **GET만 허용**: 후보가 거의 남지 않고 동해시 어댑터와도 기준이 어긋난다.
- **NetFunnel에만 일반화**: ADR 0001의 근거는 업체가 아니라 "방문자 브라우저와 같은 요청이고 예약 상태를 만들지 않는다"였다. 대기열 제품을 기준으로 삼을 이유가 없다.
- **봇 탐지 장치는 통과되면 허용**: 운영자가 장치를 강화할 때마다 깨지는 회색 지대이고, 운영자가 원하지 않는다는 의사를 무시하는 일이다.
