# 폴링 간격과 매너·법적 한계 조사

Type: research
Label: wayfinder:research
Status: resolved
Blocked by:

## Question

폴링 간격을 가능한 한 촘촘하게 잡고 싶다. 차단되거나 법적 문제가 생기지 않는 선은 어디인가?

- 공공기관이나 지자체 예약 사이트를 자동으로 조회하는 것에 대한 국내 법적 쟁점: 정보통신망법, 업무방해, 크롤링 관련 판례(예: 여기어때·야놀자 판결), robots.txt가 가지는 의미.
- 공개 스크래핑에서 통용되는 요청 빈도 관행. Crawl-delay나 흔히 권고되는 간격이 있는가?
- 고래불(stay.yd.go.kr)의 실제 특성: 응답 헤더의 `Cache-Control: max-age=36000`이 실제 데이터 신선도에 영향을 주는가? 속도 제한이나 IP 차단 징후가 있는가? 데이터센터나 해외 IP가 차단되는가? 짧은 간격으로 **소량** 조회해 보는 것은 허용한다.
- 취소로 생긴 빈자리가 얼마나 오래 남아 있는지(다른 사람이 채가기까지) 추정할 근거가 있는가?

결론: 시설 한 곳당 권장하는 최소 간격, 지터 범위, 요청 한 번에 드는 비용(캘린더 한 번 + 구역별 조회 횟수)을 정리한다.

## Answer

- **핵심 발견: stay.yd.go.kr는 비브라우저 UA를 차단한다.** curl 기본 UA로 요청하면 HTTP 200과 함께 "일반 웹브라우저 접속이 아닌 것으로 확인되어 접속이 차단되었습니다"라는 안내가 온다. 정직한 도구 UA로는 정상 응답했다. 브라우저 UA 사칭은 하지 않으며, 차단을 감지하면 폴링을 중단한다. 차단 여부는 상태 코드로 알 수 없으므로 본문으로 판정한다.
- **신선도**: `max-age=36000`은 효과가 없다. 매 응답이 새로 렌더링된다. ETag가 없어서 304 응답으로 요청을 아낄 수 없다. 세션 쿠키는 재사용한다.
- **권장 간격**: 시설 하나당 캘린더를 **60초 간격, ±25% 지터(45~75초)**로 조회한다. 예약처당 연결은 1개로 하고 요청은 직렬로 보낸다. 5xx나 지연이 생기면 지수 백오프한다(상한 30분).
- **1회 폴링 비용**: 캘린더 GET × 월 수(보통 1~2)가 기본이다. 여기에 잔여 수가 바뀐 (구역, 날짜)마다 zoneAreaAjax GET 1회가 더해진다. 월 하나를 보면 하루 약 1,440회다.
- **법적 위험(법률 자문 아님)**: 공개 페이지를 저빈도로 읽기만 하는 것은 대법원 2021도1533 기준으로 위험이 낮다. 그러나 UA 차단은 객관적인 보호조치이므로 이를 우회하면 정보통신망법 제48조상 위험이 커진다. 업무방해는 실제 장애가 있어야 성립한다. 영덕군 전산팀(054-730-6071)에 사전 문의하는 것을 권장한다.
