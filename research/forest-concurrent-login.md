# 숲나들e 동시 로그인: 사용자 브라우저 세션과 우리 세션은 서로 밀어내지 않는다 (2026-10-20)

[#139](https://github.com/ppzxc/overlord/issues/139)를 풀려고 사용자 본인 계정으로 브라우저 세션과 스크립트 세션을 동시에 열어 보았다. [ADR 0004](../docs/adr/0004-foresttrip-login-exception.md) 조건 안에서 조회만 했다. 예약, 결제, 취소, 회원정보 수정 경로는 부르지 않았다. 세션 값, 토큰, 계정 정보는 남기지 않았다.

## 핵심 결론

- **같은 계정으로 두 세션이 함께 살아 있다.** 어느 쪽도 상대를 끊지 않았다.
- 브라우저로 로그인한 뒤에도 우리 세션의 조회가 `200`이었다(로그인 후 4.4분 시점).
- 우리가 같은 계정으로 다시 로그인한 뒤에도 사용자의 브라우저 세션이 유지됐다(새로고침으로 확인).
- 로그인 중 "다른 곳에서 접속 중" 같은 중복 접속 안내는 브라우저에서 뜨지 않았다.

## 결정에 주는 뜻

- [Decision-8](https://github.com/ppzxc/overlord/issues/137)의 "로그인 직후 30분 안에 연속 2번 세션이 끊기면 `stopped`" 임시 정책에서, 사용자 접속과의 충돌이라는 설명은 근거가 사라졌다. 세션이 끊기면 원인은 유휴 만료나 서버 쪽 사정으로 읽는다.
- 사용자가 브라우저로 쓰는 중에도 우리 폴링을 멈출 이유가 없다.

## 한계

- 각 방향을 한 번씩만 시험했다. 세션 수 상한(3개 이상 동시 로그인)은 보지 않았다.
- 확인은 조회 한 번과 화면 새로고침 한 번이라, 몇 분 뒤 서버가 뒤늦게 이전 세션을 정리하는지는 모른다.
- 우리 세션의 재로그인 직후 옛 세션 값으로 다시 조회해 보지는 않았다(옛 값을 버렸다). 옛 세션이 살아 있는지는 모른다.
- 이번 재로그인에서는 비밀번호 변경 안내(`/com/alert.do`)로 가는 리다이렉트가 없었다. 첫 로그인에서는 있었다. 안내가 한 번 본 뒤 사라지는지, 사용자가 처리했는지는 모른다.

## 조사 방법

- UA는 `overlord-availability-poller/0.1 (research)`, 요청 사이는 4초 이상이다.
- 로그인 2건(둘 다 성공, `crawlingCheck.do`는 `true`), 조회 `POST` 3건(유형 목록, 모두 `200`), 메인 `GET` 2건이다. 403과 429는 받지 않았다.
