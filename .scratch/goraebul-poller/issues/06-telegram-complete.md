# 06: Telegram 알림 완성

**What to build:** 알림 메시지를 spec에서 정한 모양으로 만든다. 알림 대상을 여러 개 둘 수 있게 하고, 전송 실패에 대비한다. chatId를 찾는 CLI도 함께 만든다. 근거: [spec](../../availability-poller/spec.md)

- 알림 플러그인은 구조화된 이벤트(`openings`, `health`, `watchExpired`, `heartbeat`)를 받아 채널에 맞게 렌더링한다. 이 티켓에서는 `openings`와 `watchExpired`를 완성한다.

**Blocked by:** 02 (새 빈자리만 알리고, 전송에 성공했을 때만 기록)

**Status:** done

- [ ] 알림 대상 하나에는 한 바퀴에 메시지 한 건만 보낸다. 메시지 안에서는 감시 조건별로 블록을 나누고, 각 줄을 `날짜(요일) N박 · 구역명 · 자리 번호들` 형식으로 쓴다(HTML).
- [ ] (구역, 입실일)마다 인라인 URL 버튼을 붙인다. 버튼은 최대 8개이고, 넘치는 것은 본문 링크로 바꾼다.
- [ ] 메시지가 4096자를 넘으면 나눠 보내고, 내용이 빠지지 않는다.
- [ ] `notifiers`에 이름을 붙인 알림 대상을 여러 개 둘 수 있다. 감시 조건의 `notify` 설정에 따라 보내고, 설정이 없으면 `default`로 보낸다.
- [ ] 429를 받으면 `retry_after`만큼 기다렸다가 재시도한다. 5xx나 네트워크 오류는 최대 3회 재시도한다. 끝내 실패하면 로그를 남기고 다음 바퀴에 다시 보낸다.
- [ ] `telegram chats` CLI는 봇이 최근 받은 업데이트에서 chat 목록을 출력한다.
- [ ] 토큰과 chatId는 로그에 남기지 않는다.
