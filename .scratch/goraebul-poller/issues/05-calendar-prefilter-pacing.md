# 05: 캘린더 선필터와 요청 매너

**What to build:** 평소 한 바퀴를 요청 1~2회로 끝내고 사이트 부하를 최소로 줄인다. 고래불 월 캘린더의 잔여 수로 먼저 거르고, 잔여가 있는 곳만 자세히 조회한다. 요청 순서와 간격, 바퀴 간격은 매너 규칙을 따른다. 근거: [spec](../../availability-poller/spec.md)

- 어댑터 선택 메서드 `queryAvailabilityBatch`를 쓴다. 이 메서드가 없는 어댑터는 코어가 조회 단위마다 따로 호출한다.
- 고래불 캘린더 경로는 `/pages/sub.htm?nav_code=gor1501675800&view_cate=YYYY&view_cate2=MM`이다. 잔여 수는 `(N)`, 매진은 `(마감)`, 아직 안 열린 날짜는 `td.not`으로 표시된다.

**Blocked by:** 03 (감시 조건을 조회 단위로 전개)

**Status:** ready-for-agent

- [ ] 대상 날짜와 구역이 모두 매진이면 한 바퀴에 캘린더 요청만 나간다(대상 월 하나당 1회).
- [ ] 1박 잔여가 1 이상인 (구역, 날짜)만 자리 배치를 자세히 조회한다.
- [ ] 한 예약처로 가는 요청은 순서대로 나가고, 요청 사이는 최소 5초에 0~3초 지터를 더한 간격을 둔다.
- [ ] 다음 바퀴는 이전 바퀴가 끝난 뒤 설정 간격(기본 150초)에 ±20% 지터를 적용한 시간이 지나야 시작한다.
- [ ] 예약처가 여럿이면 첫 바퀴 시작 시각을 분산한다.
