# 07: 헬스 상태 머신과 실패 처리

**What to build:** 폴러가 감시를 못 하는 상태를 사용자가 알 수 있게 한다. 차단당하면 사이트에 계속 요청을 보내지 않는다. 한 예약처에 문제가 생겨도 다른 예약처는 영향을 받지 않는다. 근거: [spec](../../availability-poller/spec.md)

- 실패는 `transient`, `blocked`, `unrecognized`, `unavailable` 네 종류로 나눈다.
- 예약처별 상태: `ok`, `degraded`, `unavailable`, `stopped(blocked|unrecognized)`. health 이벤트는 상태가 바뀔 때만 보낸다.

**Blocked by:** 05 (캘린더 선필터와 요청 매너)

**Status:** done

- [ ] 차단 페이지를 받으면(HTTP 200이어도 본문으로 판별) 그 예약처의 폴링을 즉시 멈춘다. 원인과 조치 방법(재시작)을 담은 알림을 보낸다.
- [ ] 구조 검증(캘린더 셀 수, `div.select_room` 존재, 자리 수)이 한 번 실패하면 계속 돈다. 연속 2바퀴 실패하면 `unrecognized`로 멈춘다.
- [ ] transient 실패가 나면 다음 바퀴까지 간격을 두 배로 늘린다(상한 30분). 성공하면 원래 간격으로 돌아온다. 같은 바퀴 안에서 즉시 재시도하지 않는다.
- [ ] transient가 5바퀴 이상, 15분 이상 이어지면 `degraded` 알림을 한 번 보낸다. 회복하면 `recovered`를 한 번 보낸다.
- [ ] 점검이나 휴장 상태(`unavailable`)면 30분 간격으로 계속 확인하고, 알림은 한 번만 보낸다.
- [ ] 같은 장애 상태가 이어지면 24시간마다 한 번만 리마인드한다.
- [ ] 한 예약처가 멈춰도 다른 예약처(테스트용 가짜 어댑터)는 계속 돈다.
- [ ] 바퀴 도중 실패하면 그 바퀴를 중단한다. 이미 성공한 조회 결과는 반영한다.
