# 동해시 예약처의 NetFunnel 대기열에 정상 참여하고, 예약 상태를 바꾸지 않는 POST를 허용한다

동해시 예약처(campingkorea.or.kr)의 빈자리 화면은 NetFunnel `reserve` 대기열 뒤에 있다. 대기열에서 받은 키를 `ND_setNfKey.do`로 서버 세션에 등록하고 `BD_reservation.do`를 POST해야 들어간다. 지금까지는 "읽기 전용 GET 위주"로 폴링했지만, 이 흐름은 GET만으로 끝나지 않는다.

그래서 `donghae` 어댑터는 `netfunnel.js`가 보내는 `ts.wseq` 호출(5101 → 5002 반복 → 5004 setComplete)을 Node HTTP로 똑같이 보낸다. 원칙은 "페이지 JS가 하는 일만, 그 순서와 간격대로"다. 키는 페이지처럼 같은 세션에서, 예약처 TTL(2시간) 안에서, 서버가 받아 주는 동안 쓴다. 조회 흐름에서 브라우저가 보내는 요청이고 예약 상태를 바꾸지 않는다면 POST도 보낸다. 예약, 결제, 취소, 회원정보 경로는 접근 금지 목록에 넣는다. NetFunnel이 301(Block)이나 302(IP Block)를 돌려주면 곧바로 `blocked`로 보고 멈춘다. 302의 가상대기에는 참여하지 않는다.

## 고려한 대안

- **헤드리스 브라우저(Playwright)로 실제 페이지 JS 실행**: 브라우저와 똑같이 동작한다는 보장은 가장 강하다. 하지만 Docker 이미지와 의존성이 크게 늘어난다. 기존 폴러의 HTTP 층(요청 간격, 지터, 헬스 판정)도 쓸 수 없다. 프로토콜 구현이 페이지 동작을 따라가지 못하게 되면 다시 본다.
- **바퀴마다 대기열에 새로 참여**: 150초마다 줄을 서게 되어 대기열 부하가 오히려 커진다.
- **no-go(동해시 어댑터 포기)**: 위 흐름은 로그아웃한 방문자의 브라우저가 보내는 요청과 같고 예약 상태를 만들지 않는다. 그래서 포기할 이유가 되지 못했다.

## 결과

- HTTP 클라이언트에 POST와 예약처별 쿠키 세션을 더해야 한다.
- 금지하는 "키 재사용"은 세션 사이로 키를 옮기는 것, 만료된 키를 쓰는 것, 키 위조다. 대기 단축과 `localStorage.nfdebug1`·localhost 우회도 금지한다.
- 대기열이 붐비는 오픈 경쟁 시간에는 바퀴를 돌지 않는다. 대기가 상한을 넘으면 그 바퀴를 일시 오류로 처리한다.
