## Question

폴러를 어떤 언어, 런타임, 핵심 라이브러리(HTTP 클라이언트, HTML 파서, 브라우저 자동화, 스케줄러)로 만들 것인가?

## Progress (2026-09-29 세션)

- 언어: **TypeScript/Node**로 정했다 (사용자).
- 크롤링 프레임워크: **쓰지 않는다** (사용자). 근거는 [크롤링 프레임워크 표준 조사](11-crawling-framework-survey.md)에 있다.
- 이미지에 브라우저를 넣을지: **넣지 않는다.** 첫 이미지는 브라우저 없이 만든다. 브라우저가 필요한 예약처가 생기면 그때 추가한다 (사용자).

## Answer

- **언어·런타임**: TypeScript / Node.
- **HTTP**: Node 내장 `fetch`. 요청에는 반드시 코어가 제공하는 공통 클라이언트를 거친다. 이 클라이언트가 정직한 UA, 요청 간격, 차단 감지를 맡는다.
- **HTML 파싱**: `cheerio`.
- **스케줄**: 직접 만든 루프를 쓴다. cron 표현식이 필요해지면 `croner`를 추가한다.
- **쿠키**: 필요한 예약처가 생기면 `tough-cookie`를 쓴다. 고래불에는 필요 없다.
- **브라우저**: 첫 구현에는 없다. Playwright는 필요한 어댑터 안에만 두고, 선택 의존성이나 dynamic import로 분리한다. 그래서 브라우저가 필요 없는 이미지에는 들어가지 않는다.
- **크롤링 프레임워크(Crawlee, Scrapy 등)는 쓰지 않는다.** 상주 폴러와 구조가 맞지 않는다. 위장, 세션 로테이션, robots 무시 같은 기본값이 윤리 원칙과 충돌한다. 앱 전체를 감싸는 구조라 예약처마다 수집 방식을 고르기도 어렵다.

참고: 폴링 조사가 권한 60초는 당시 권장값이었다. 운영 간격은 사용자가 정한 150초다(map Notes).
